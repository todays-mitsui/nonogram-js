# Glossary (v0.11)

ノノグラム作問・プレイ用ライブラリ(WordPress 非依存)のための用語集。
このパズルの日本語での総称は「**ノノグラム**」とし、UI・ドキュメントで統一する。
コード上の識別子・UI 文言・ドキュメントはここの用語に揃える。

- **識別子** はコードで使う英語名(型名・変数名の語幹)
- **旧コード** は `wp-block-nonogram` での呼び方。参考として残すだけで、基準にはしない
- 用語は、一般的な呼び方(末尾「参考: 外部での呼び方」)を下敷きにして選ぶ
- カラーパズルを前提に定義する。モノクロは「パレットが1色だけのパズル」として扱い、特別扱いしない
- **ハッカブルであることを優先する**。正解図はページに同梱し、その形式は公開仕様とする。正解図を復元できてしまうことは受け入れる
- ⚠️ は未決事項(末尾「Open Questions」参照)。(予約)は将来の機能のために名前だけ確保した語(「予約語」参照)

---

## 1. 役割とモード

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| 作問者 | `Author` | パズルを作る人 | — |
| 解答者 | `Solver` | パズルを解く人 | player |
| 作問モード | `Editor` | 作問者がパレットと正解図を作り、サイズを決める画面・コンポーネント | `Edit` (edit.jsx) |
| プレイモード | `Player` | 解答者がヒントを見て盤面に記入する画面・コンポーネント | `GameView`, view.js |
| (予約)鑑賞モード | `Viewer` | 正解図を、ヒントも盤面もなしに絵として表示するモード。ドット絵としての利用を想定。名前を予約しておく | — |

### データの流れ

1. 作問モード(WordPress なら編集画面)で、作問者がパレットと正解図を作る
2. 作問側の保存では、正解図を**データ領域ごと**正解図コードにエンコードする(WordPress ならブロック属性)。可視領域の外に描いたマスも失われない
3. 解答者向けには正解図を**書き出す**。可視領域に切り抜いてからエンコードした正解図コードを、**埋め込み要素**の data 属性に置く
4. プレイモードは正解図コードをデコードし、正解図からヒントを導出して**パズル**として提示する

## 2. パズルの構造

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| パズル | `Puzzle` | プレイモードが解答者に提示する問題。正解図の可視領域から導出する。**サイズ・パレット・全ラインのヒント**から成り、正解図は含まない | (rowClues + columnClues の組) |
| グリッド | `Grid<T>` | マスを長方形に並べた構造。行・列・ラインを持つ。**ヒントは含まない**。マスの値の型 `T` は使う側が決める。座標・ラインの取り出し・リサイズなど、構造に関する操作はここに置く | `Grid`(保存用の内部クラス) |
| 正解図 | `Solution` | `Grid<empty \| PaletteIndex>` と可視領域の組。作問者が描いた絵。グリッドはデータ領域全体を持つ。各マスの値は `empty`(背景)か `PaletteIndex`(その色で塗る)。ヒントは可視領域の中だけから導出される | `Board`(作問時) |
| サイズ | `Size` / `width`, `height` | **可視領域**の列数 × 行数。表記は `幅x高さ`(例 `15x10`)。UI で「サイズ」と言えばこれ | `numColumns`, `numRows` |
| 可視領域 | `Frame` | パズルとして見せる範囲。左上 `(0, 0)` からサイズ分の長方形 | — |
| データ領域 | `Extent` | データを保持している範囲。可視領域と、背景以外のマスをすべて含む最小の長方形。左上は `(0, 0)` 固定で、広がるのは右と下だけ | — |
| 枠外 | outside frame | データ領域のうち可視領域に入らない部分。そこにあるマスを「枠外のマス」と呼ぶ。サイズを縮めても枠外のマスは消えず、サイズを戻せば再び見える | — |
| 切り抜き | `crop` | データ領域を可視領域に切り詰める操作。枠外のマスは捨てる | — |
| マス | `Cell` | 格子の1区画 | cell |
| 座標 | `x`, `y` | マスの位置。左上原点・0 始まり。`x` = 列番号、`y` = 行番号 | 同じ |
| 行 | `Row` | 横一列のマス。上から `y = 0, 1, …` | row |
| 列 | `Column` | 縦一列のマス。左から `x = 0, 1, …` | column |
| ライン | `Line` | 行または列の総称。`{ axis: 'row' \| 'column', index }` で指す | — |
| ブロック | `Block` | ライン上で連続する**同じ色**の塗りマスの塊。ルール: 同じ色のブロック同士の間には1マス以上の背景が要る。違う色のブロック同士は隙間なしで隣接してよい | — |
| ヒント | `Clue` | 1ライン分のヒント。ヒント項目の列(`ClueEntry[]`)。行は左→右、列は上→下の順 | `clue` / `clues`(混在) |
| ヒント項目 | `ClueEntry` | ヒントを構成する1要素 = 1つのブロックの記述。`{ length, paletteIndex }` | `num` |
| 長さ | `length` | ヒント項目が表すブロックのマス数。UI 上でヒントとして表示される「数字」 | — |
| 行ヒント / 列ヒント | `rowClues` / `columnClues` | 全行・全列のヒントの配列(`Clue[]`) | 同じ |
| 空ライン | — | 塗りマスが1つもないライン。ヒントは `[]` で表し、表示上は「0」。ブロック数 = ヒントの配列の長さ、の対応を崩さないため | `[0]` |

### 「ヒント」と「Hint」

| 文脈 | 語 |
|---|---|
| 縁の数字(コード) | `Clue` |
| 縁の数字(日本語・UI) | ヒント |
| 行き詰まった解答者を助ける補助機能(将来。例: 正解図と照らして間違っているマスを教える) | コード: `Hint` / 日本語: ヒントとは別の語(「お助け」など) |

日本語の「ヒント」と英語の "hint" は指すものがずれているので、コードで縁の数字を `Hint` と呼ばない。

## 3. パレット

| 用語 | 識別子 | 定義 |
|---|---|---|
| パレット | `Palette` | パズルで使う色の順序付きリスト(`PaletteColor[]`)。パズルの一部として解答者にも提示する |
| パレット色 | `PaletteColor` | パレットの1要素。色の値(`#RGB` または `#RRGGBB`)だけを持つ。名前は持たない |
| パレットインデックス | `PaletteIndex` | パレット内の位置。**0 始まり**(`palette[i]` の `i`)。正解図・ヒント・盤面はすべてこれで色を参照し、色の値を直接持たない |
| 表示番号 | — | UI 上の色の番号。`PaletteIndex + 1`(「色1」「色2」…) |
| 背景 | `empty`(正解図)/ `crossed`(盤面) | どの色でも塗らないマス。**パレットに含めず、`PaletteIndex` を持たない** |
| モノクロ問題 | `monochrome` | パレットが1色のパズル。「モノクロ」は色数の話で、黒かどうかは問わない(赤1色でもモノクロ問題) |
| カラー問題 | `color` | パレットが2色以上のパズル |
| (判定) | `isMonochrome(puzzle)` | `palette.length === 1`。**パレットから導出する値で、別のフィールドとして保存しない**(「2色なのに monochrome」のような食い違いを防ぐため) |

- パレットの色を並べ替えたり削除したりしたら、正解図の `PaletteIndex` の振り直しはエディタの責務とする
- 色の値(`value`)の変更はパズルの同一性に影響しない(→ パズル ID)
- モノクロ問題とカラー問題で内部処理は分けない。違いが出るのは表示だけ(ツールバーの候補、ヒント数字の色付け、ブロック間の隙間ルールの説明)

## 4. プレイ状態

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| 盤面 | `Board` | `Grid<Mark>`。解答者が記入中の状態。各マスに「記号」を持つ。常に可視領域 = データ領域で、データ領域の概念は持ち込まない | `Board`(プレイ時) |
| 記号 | `Mark` | 盤面の各マスの状態。`blank` / `crossed` / 塗り(`PaletteIndex`)のいずれか | `status` |
| 未記入 | `blank` | 何も書いていないマス | `'unknown'` |
| 塗り | `filled` | 解答者が特定の色で塗ったマス。どの色かを `PaletteIndex` で持つ | `'filled'` |
| バツ | `crossed` | 解答者が「どの色でも塗らない(背景)と確定」と判断して × を付けたマス | `'space'` |
| 一致したヒント | `satisfied` | 盤面のそのラインから導出したヒントが、パズルのヒントと(長さ・色とも)一致している状態。表示はグレーアウト | `completion`, `cluesCompletions` |
| 解けた | `solved` | 全ラインのヒントが一致した状態。プレイモードは正解図を持っているが、**正解図との一致ではなくヒントとの一致で判定する**。別解がある問題で、正しく解いたのに不正解扱いになるのを避けるため | 未実装 |
| ギブアップ | `giveUp` | 解答者が解くのを諦めて正解を見る操作 | — |
| 正解表示 | `revealed` | ギブアップ後の状態。盤面の代わりに正解図を表示する。「解けた」(`solved`)とは区別する | — |
| リセット | `reset` | 盤面を全マス未記入に戻す操作 | `clearAll`("Clear All") |

> 「empty」は正解図側だけ、「blank」は盤面側だけで使う。混ぜない。

## 5. 操作

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| 主操作 | `primary` | タップ / 左クリック。現在のツールをマスに適用する | — |
| 副操作 | `secondary` | 右クリック、または Alt / Ctrl / Shift + クリック。マウス利用者向けのショートカットで、**現在のツールに関係なく**バツを付ける・外す。作問モードにはバツがないので、背景にする(消しゴムと同じ)。タッチ操作はツールバーだけで完結させる | `isRightClick` |
| ストローク | `Stroke` | ポインタを押してから離すまでの一連の操作。最初のマスで決まった記号を、なぞったマスに同じく適用する。プレイモードでは、最初に動いた向き(行か列)にストロークを固定し、そのライン上のマスだけに適用する(方向の固定)。作問モードでは固定せず、なぞったマスすべてに適用する | `nextStatus`(ドラッグ中保持) |
| 記号遷移 | `nextMark` | 現在の記号・操作種別・現在のツールから次の記号を決める規則 | `decideNextStatus*` |

### ツール

| 用語 | 識別子 | 定義 |
|---|---|---|
| ツール | `Tool` | 主操作でマスに何をするか。下の3種のいずれか |
| 塗りツール | `{ kind: 'paint', paletteIndex }` | 指定した色で塗る。**すでに同じ色で塗られたマスに適用すると未記入(作問モードでは背景)に戻す(トグル)**。最初のマスがそうなったストロークは、全体が「消す」になる |
| バツツール | `{ kind: 'cross' }` | バツを付ける。すでにバツのマスに適用すると未記入に戻す(トグル。副操作と揃える)。作問モードにはない |
| 消しゴム | `{ kind: 'erase' }` | 未記入(盤面)/ 背景(正解図)に戻す |
| 現在のツール | `activeTool` | いま選ばれているツール。**保存しない**。開いた時点では塗り(色0)から始まる |

ツールの候補は、パズルの種類とモードで決まる。

| | モノクロ問題 | カラー問題 |
|---|---|---|
| プレイモード | 塗り(色0)/ バツ / 消しゴム。UI 上は「塗る / × / 消す」 | 塗り(色ごと)/ バツ / 消しゴム |
| 作問モード | 塗り(色0)/ 消しゴム | 塗り(色ごと)/ 消しゴム |

### ツールバー(UI)

| 用語 | 識別子 | 定義 |
|---|---|---|
| ツールバー | `Toolbar` | ツールを切り替える画面上の UI。マウスとタッチの両方で使う |
| ツールボタン | `ToolButton` | ツールバー上の1つのボタン。押すとそのツールが現在のツールになる |
| 色見本 | `Swatch` | 塗りツールのツールボタン。パレット色を表示する |

## 6. 永続化・識別

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| パズル ID | `PuzzleId` | ヒント(長さと `PaletteIndex`)から決定的に計算する識別子(SHA-256 の16進。正規形は [PROGRESS.md](PROGRESS.md))。**色の値も色数も含めない**ので、作問者が色味だけ変えても解答者の進捗は保たれる。進捗の持ち主を示す。ヒントが同じ別解パズル同士は同じ ID になり進捗を共有するが、解答者から見て同じ問題なので意図どおりとする | `cluesDigest` |
| 進捗 | `Progress` | 解いている途中の状態全体。リロード後に復元すべきものの集まりで、盤面と正解表示(`revealed`)かどうかを持つ。**解けた(`solved`)は盤面から導出できるので入れない** | (盤面のみ保存していた) |
| 進捗コード | `ProgressCode` | 進捗を文字列にしたもの。localStorage に保存する値。フォーマットバージョン(`p1`)を先頭に持つ。詳細は [PROGRESS.md](PROGRESS.md) | `Board.serialize()` の結果 |
| エンコード / デコード | `encodeProgress` / `decodeProgress` | 進捗と進捗コードの相互変換 | — |
| 保存キー | `StorageKey` | localStorage のキー。`todays-mitsui/nonogram:progress:<PuzzleId>` の形。接頭辞は埋め込み要素のクラス名と同じく、ブログの他のスクリプトとの衝突を避けるため | `nonogram-level-${digest}` |
| 正解図コード | `SolutionCode` | 正解図を文字列にしたもの。中身はフォーマットバージョン・可視領域のサイズ・データ領域のサイズ・パレット・マスデータ。詳細は [FORMAT.md](FORMAT.md)。作問モードが保存し、プレイモードが読み込む**唯一の受け渡し形式**。1つの形式で、作問側の保存(可視領域 ⊆ データ領域)と書き出し後(可視領域 = データ領域)の両方を表す。形式は公開仕様とし、外部ツールで作ったり読んだりしてよい。文字列にする目的は、ページのソースを見ただけで答えが分からない程度の**ネタバレ防止**で、秘匿ではない | `boardData` (`v1;WxH;WxH;…`) |
| マスデータ | `cells` | 正解図コードの末尾のフィールド。データ領域のマスを行優先に1マス1バイトで並べ、raw deflate で圧縮し、base64url(パディングなし)にしたもの | — |
| マスの値 | — | マスデータの1バイト。`0` = 背景、`i + 1` = `PaletteIndex` が `i` の色 | `serial`(0/1/2) |
| エンコード / デコード | `encodeSolution` / `decodeSolution` | 正解図と正解図コードの相互変換 | `serialize` / `deserialize` |
| 書き出し | `export` | 解答者向けの正解図コードを作る操作。切り抜いてからエンコードする | `save.jsx`(ヒントを出力していた) |
| フォーマットバージョン | `formatVersion` | 正解図コード・進捗コードの先頭に入れる版番号。**旧形式(`v1;WxH;WxH;…`)とは互換を持たない**。旧データとの取り違えを避けるため、新形式では `v1` を使わない。正解図コードの現行版は `v2` | `v1` |
| (対応関係) | — | 正解図 ⇄ 正解図コード は data 属性に置く作問者のもの。進捗 ⇄ 進捗コード は localStorage に置く解答者のもの | — |
| 埋め込み要素 | `MountElement` | 書き出した正解図コードを data 属性(`data-solution`)に、表示設定を別の data 属性(`data-aspect-ratio` など)に持ち、ウィジェットが描画される HTML 要素 | `.wp-block-todays-mitsui-nonogram` |

## 7. 表示・レイアウト

| 用語 | 識別子 | 定義 | 旧コード |
|---|---|---|---|
| ウィジェット | `Widget` | 埋め込み要素の中に描画されるノノグラム一式。キャンバス・ツールバー・操作ボタン(リセット、ギブアップ、罫線表示など)を含む。縦横比はこれに対して設定する。埋め込み要素が HTML 上の置き場所であるのに対し、ウィジェットはレイアウトの概念で、WordPress なしで使う場面でも同じ語を使う | ブロックの `div` |
| キャンバス | `Canvas` | ウィジェットのうち、ヒント領域とマス領域を描く部分。大きさは、ウィジェットからツールバーなどを除いた残りで決まる | `Stage`, `width`/`height` |
| マス領域 | `CellArea` | マスが並ぶ領域 | `CellsView` |
| ヒント領域 | `ClueArea` | 行ヒント領域(左)と列ヒント領域(上)の総称 | `cluesWidth`, `cluesHeight` |
| マスサイズ | `cellSize` | 1マスの一辺の長さ(px) | 同じ |
| 罫線 | `GridLine` | マスの境界線 | `GridView` |
| 区切り線 | `MajorLine` | 5 マスごと(と外周)の濃い罫線 | `i % 5 === 0` |
| 罫線表示 | `showGridLines` | 外周以外の罫線を表示するか。非表示時はバツも隠れる | `showGrid` |
| 縦横比 | `aspectRatio` | ウィジェットの縦横比。値は `'3:4'` / `'1:1'` / `'4:3'` のいずれかで、比の文字列のまま持つ。UI ではそれぞれ「縦長」「正方形」「横長」と見せる | `aspectRatio`(`[w, h]`。1:1 / 3:2 / 2:3) |
| 表示設定 | `DisplayOptions` | パズルの中身ではなく、ウィジェットの見せ方に関する設定の集まり。現時点では縦横比のみ。**正解図コードには入れず**、埋め込み要素の別の data 属性に置く | — |

## 8. 採用しなかった語

| 語 | 理由 | 代わりに |
|---|---|---|
| `Hint`(縁の数字として) | 英語では補助機能を指すのが普通。将来の補助機能と衝突する | `Clue` |
| `ClueNumber` | カラー対応でヒントの要素が数字だけではなくなった | `ClueEntry` |
| `PaletteNumber` | 「数字」はヒントの数字と衝突する。1 始まりを想起させ、配列アクセスとずれる | `PaletteIndex` |
| `PaletteId` | 並べ替えても変わらない安定 ID を想起させるが、実際は位置で参照する。`PuzzleId`(ハッシュ)とも Id の意味がそろわない | `PaletteIndex` |
| `isFilled` | 正解図が 2 値ではなくなった | `empty \| PaletteIndex` |
| `activePaletteIndex`(選択色) | 塗り以外(バツ・消しゴム)の選択状態を表せない | `activeTool` |
| モノクロ / カラーの「モード」 | パズルが元から持つ性質で、利用者が切り替えるものではない。「モード」は作問 / プレイで使用済み | モノクロ問題 / カラー問題(`isMonochrome`) |
| パズル種類の保存フィールド | パレットと食い違いうる | `isMonochrome(puzzle)` で導出 |
| `Run` | 衝突回避の代案だったが、一般的な語ではない。WP 非依存にしたので「WP ブロック」との衝突は WordPress 用アダプタ内に限られる | `Block` |
| `space`(バツの識別子として) | 一般用語としては正しいが、空白文字と紛らわしい。ツール名 `cross`・UI の × と揃わない | `crossed` |
| 空ラインのヒント `[0]` | 「長さ0のブロックが1つ」と読めてしまう | `[]` |
| 現在のツールの保存 | ツールはパズルごとの状態ではなく、その場の操作の都合 | 保存しない |
| 旧形式(`v1;…`)の読み込み互換 | 互換は捨てる判断をした | なし |
| 「お絵かきロジック」「イラストロジック」「ピクロス」(総称として) | 識別子・リポジトリ名と揃わない。「ピクロス」は任天堂の商標 | ノノグラム |
| `Canvas`(可視領域の名前として) | 表示・レイアウトの「描画領域全体(px)」で使用済み | `Frame` |
| `Viewport`(可視領域の名前として) | スクロール・ズームで見えている範囲を想起させる。エディタに将来ズーム等を付けたときのために空けておく | `Frame` |
| `PaletteColor.name`(色の名前) | 表示番号で足りる。色覚への配慮は名前では解決しない。区切り文字のエスケープや UI 言語の問題を持ち込む | 表示番号「色1」「色2」 |
| 透明度付きの色(`#RRGGBBAA`) | 背景がパレット外という定義と噛み合わない | `#RGB` / `#RRGGBB` のみ |
| ビットパック(色数に応じて1マス1〜4ビット) | 実際のドット絵では deflate の方が小さくなる。色数ごとの場合分けが仕様を複雑にする | 1マス1バイト + raw deflate |
| 標準の base64 | URL での共有に使えない | base64url(パディングなし) |
| `Stage`(ウィジェットの名前として) | 日本語の「ステージ」はゲームでは面・レベルを指すのが普通。Konva の Stage(canvas 要素)とも紛らわしい | `Widget` |
| `Screen`(ウィジェットの名前として) | 端末の画面と紛らわしい。モードの説明で「画面」を使っている | `Widget` |
| 縦横比を正解図コードに入れる | パズルの中身ではなく表示の設定 | 表示設定として別の data 属性に置く |
| `Pen` | 「バツのペン」「消しゴムのペン」が不自然 | `Tool` |
| `ToolPalette` | 描画アプリでは一般的だが、`Palette`(色のリスト)と衝突する | `Toolbar` |
| `PuzzleCode` | 中身は正解図であり、「パズル = 正解図を含まない」の定義と食い違う。名前に Solution が入っていれば答えを含むデータだと一目で分かる | `SolutionCode` |
| `ClueCode`(ヒントコード) | 正解図コード1本に一本化した。ヒントはプレイモードで導出する | 廃止 |
| 難読(化) | 「隠したい」意図に読め、ハッカブルにしたい方針と逆に伝わる | ネタバレ防止 |
| `Board`(マスの集まりの総称として) | 正解図まで Board と呼ぶのは不自然。ヒントを含む盤全体とも受け取られやすい。総称に回すと解答者の記入状態に別名が要る | 総称: `Grid` / 解答者の記入状態: `Board` |

### 旧コードから廃止する語

| 旧 | 理由 | 新 |
|---|---|---|
| `status` | 汎用的すぎる。正解図と盤面で意味が違う | 盤面: `Mark` / 正解図: `empty \| PaletteIndex` |
| `'unknown'` | 「不明」ではなく「未記入」 | `blank` |
| `'space'` | 一般用語としては正しいが、空白文字と紛らわしく、UI 上の見た目(×)とも名前が合わない。旧コード内でも「unknown 以外」の意味で `nonSpace` を使っていて混乱あり | `crossed` |
| `Board`(作問時) | 正解図と盤面が同じクラスだった | `Solution` |
| `Game` | 未使用の器 | 廃止(`Player` が担う) |
| `level` | パズルと同義で揺れ | `Puzzle` |
| `completion` | 「完成」と紛らわしい | `satisfied` |
| `playerAnswer` | 実体は盤面から導出したヒント | `derivedClues` |
| ドットのある範囲より小さく縮められない挙動 | サイズを縮めても枠外のマスを保持すればよい | 可視領域とデータ領域の分離 |
| 縦横比の選択肢 3:2 / 2:3 | 選択肢を見直した | 3:4 / 1:1 / 4:3 |
| `clues`(1ライン分) | 複数形が1ライン分と全ライン分の両方に使われていた | 1ライン: `clue` / 全体: `rowClues` 等 |

## 参考: 外部での呼び方

調べた範囲では、標準と言える語彙は確立していない。特に「白」「empty」は、未確定のマスにも、塗らないと確定したマスにも使われていて揺れが大きい。

| 概念 | 英語での例 | 日本語での例 |
|---|---|---|
| 縁の数字 | clue, number clue | ヒント、数字のヒント、塗り指示 |
| 連続した塗りマス | block (block of boxes) | ブロック、連続した塗り |
| 塗ったマス | box, filled, occupied | 黒マス、塗りつぶしたマス |
| 塗らないと確定したマス | space, dot / cross, vacant, `x` | ×のマス、白(確定) |
| 未確定のマス | (名前なし), unknown, empty cell | 未確定、白(未確定)、空白のマス |
| 行 / 列 / その総称 | row / column / line | 行 / 列 / — |
