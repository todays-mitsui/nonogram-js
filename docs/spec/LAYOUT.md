# 表示の階層

プレイモードと作問モードが、画面上でどんな領域の入れ子になっているかと、各領域に何のデータを描くか。用語は [GLOSSARY.md](GLOSSARY.md) §7 に従う。

図の読み方: 左は画面上の領域、`←` の右はその領域に描くデータ。

---

## プレイモード

```
埋め込み要素 MountElement             data-solution / data-aspect-ratio
└─ ウィジェット Widget                 幅 = 埋め込み要素いっぱい
   ├─ キャンバス Canvas                高さ = 幅 × 縦横比
   │  ├─ パズル領域 PuzzleArea         中央寄せ。はみ出たらスクロール
   │  │  ├─ ヒント領域 ClueArea        ← パズルのヒント Clue[](rowClues / columnClues)
   │  │  │  ├─ 行ヒント領域(左)
   │  │  │  └─ 列ヒント領域(上)
   │  │  └─ マス領域 CellArea          ← 盤面 Board = Grid<Mark>(正解表示中は正解図 Grid<SolutionCell>)
   │  └─ ステータス                    解けた / 正解表示。キャンバスに重ねる
   └─ ツールバー Toolbar               ツールボタン・操作ボタン
```

- 大きさは外から内へ決まる(→ 大きさの決まり方)
- 縦横比を付けるのはキャンバスで、パズル領域ではない。パズル領域の形はパズルで決まるので、縦横比はそれを置く枠の形を決めるだけ

## 作問モード

```
エディタのページ
├─ ヘッダー                            作品名・作品の一覧
├─ 作業領域
│  ├─ キャンバスパネル
│  │  ├─ キャンバス Canvas             高さ = min(72vh, 880px)。縦横比は使わない
│  │  │  └─ パズル領域 PuzzleArea      中央寄せ。はみ出たらスクロール
│  │  │     ├─ ヒント領域 ClueArea     ← 正解図の可視領域から導出したヒント Clue[]
│  │  │     └─ マス領域 CellArea       ← 正解図の可視領域 Grid<SolutionCell>
│  │  ├─ 枠外のマスの注記              枠外に塗ったマスがあるときだけ
│  │  └─ ツールバー Toolbar            ツールボタン・アンドゥ / リドゥ
│  └─ サイドバー
│     ├─ サイズ・パレットのパネル
│     ├─ 一意解チェックのパネル
│     │  └─ パズル領域 PuzzleArea      ← 別解 Grid<SolutionCell>(別解があるときだけ。縮小表示)
│     └─ 書き出し・読み込みのパネル
└─ ダイアログ
   ├─ 作品の一覧
   └─ テストプレイ
      └─ ウィジェット Widget           ← 書き出す正解図。中身はプレイモードと同じ
```

- 描くのは可視領域だけ。枠外のマス(データ領域のうち可視領域の外)は描かず、注記で知らせる
- ヒントは保存せず、描くたびに正解図から導出する。一致したヒント(`satisfied`)のグレーアウトはしない
- なぞっている間はパズル領域の大きさを固定する。描くとヒントの項目数が変わり、マス領域がずれて指の下のマスが変わってしまうため

## 2つのモードの違い

| | プレイモード | 作問モード |
|---|---|---|
| 外枠 | ウィジェット(埋め込み要素の中) | エディタのページ全体 |
| キャンバスの高さ | 幅 × 縦横比 | 画面の高さから決める(`min(72vh, 880px)`) |
| マス領域に描くもの | 盤面 `Grid<Mark>` | 正解図の可視領域 `Grid<SolutionCell>` |
| ヒント領域に描くもの | パズルのヒント(正解図コードから一度だけ導出) | 正解図から描くたびに導出したヒント |
| ステータス | キャンバスに重ねる | なし(一意解チェックはサイドバー) |

## 大きさの決まり方

外から内へ決まる。キャンバスの大きさが変わったら(`ResizeObserver`)計算し直す。

1. **キャンバス**の大きさを決める
   - プレイモード: 幅 = ウィジェットの内側の幅(埋め込み要素の親の幅いっぱい)、高さ = 幅 × 縦横比(`aspectRatio`)。ウィジェットの高さは、これにツールバー・操作ボタンの高さを足したもの。縦横比をウィジェット全体ではなくキャンバスに付けるのは、ツールバーの折り返しでパズル領域の大きさが変わらないようにするため
   - 作問モード: 幅 = キャンバスパネルの幅、高さ = `min(72vh, 880px)`(下限 320px)
2. **`cellSize`** を決める。ヒント項目1つにマス1つ分の場所を割り当て、パズル領域がキャンバスに収まる最大の `cellSize` を求め、16〜40px に丸める
3. **パズル領域**の大きさが決まる。幅 = (行ヒントの最大項目数 + パズルの幅)× `cellSize`、高さ = (列ヒントの最大項目数 + パズルの高さ)× `cellSize`。キャンバスより小さければ中央に置く
4. 16px を割るときは 16px にし、**キャンバスの中でスクロール**させる。マス領域ではなぞってもスクロールにならないので、スクロールはヒント領域かスクロールバーで行う

- ズーム・全画面表示はしない
- 計算は `computeLayout`(`src/render/layout.ts`)。キャンバスの大きさを受け取り、`Layout`(`cellSize`、マス領域の位置 `cellAreaX` / `cellAreaY`、パズル領域の大きさ `puzzleAreaWidth` / `puzzleAreaHeight`、スクロールが要るか `overflows`)を返す
- DOM との対応: キャンバスは `.canvas-area`、パズル領域は `<canvas class="puzzle-area">`

## パズル領域の中

2つのモードで共通。

```
パズル領域 PuzzleArea
├─ ヒント領域 ClueArea
│  ├─ 行ヒント領域(左)              ← rowClues: Clue[]
│  │  └─ 1行分のヒント(横の帯)      ← Clue = ClueEntry[]
│  │     └─ ヒント項目(1マス分の枠)  ← ClueEntry { length, paletteIndex }
│  └─ 列ヒント領域(上)              ← columnClues: Clue[](縦の帯。中は行と同じ)
└─ マス領域 CellArea                ← Grid<T>
   ├─ マス Cell (x, y)              ← T(盤面なら Mark、正解図なら SolutionCell)
   └─ 罫線 GridLine / 区切り線 MajorLine
```

ライン(行・列)はこの木に入らない。1つのマスは行と列の両方に属するので、入れ子にならない。ラインはマス領域を横・縦に切り出した切り口で、**ヒント領域とマス領域をまたぐ**。

```
                   列ヒント領域
                 ┌───┬───┬───┐
                 │ 2 │ 1 │ 2 │
       ┌───┬───┐ ├───┼───┼───┤
行 y=0 │ 1 │ 1 │ │ ■ │   │ ■ │   ← 行 y=0 のヒント [1, 1] と、行 y=0 のマス
       ├───┼───┤ ├───┼───┼───┤
行 y=1 │   │ 3 │ │ ■ │ ■ │ ■ │   ← 行 y=1 のヒント [3] と、行 y=1 のマス
       └───┴───┘ └───┴───┴───┘
       行ヒント領域   ↑
                   列 x=1 のヒント [1] と、列 x=1 のマス
```

- ヒント項目の枠は、マスと同じ `cellSize` の正方形。行ヒントは右寄せ、列ヒントは下寄せで並ぶので、ヒント領域とマス領域は1つの格子として揃う
- ヒント項目1つが、そのラインのブロック(`Block`)1つに対応する。ブロックはデータ上の概念で、画面上の領域としては持たない
- 一致したヒント(`satisfied`)の判定とグレーアウトはライン単位。ヒント項目単位ではない

## 共通

- パズル領域から内側は、2つのモードで同じ計算(`computeLayout`)と同じ描画(`draw`)を使う。作問者が見ている絵とヒントは、解答者に見える形と同じになる
- パズル領域の中身をデータで言えば、ヒント(`Clue`)とグリッド(`Grid`)。ヒントはヒント領域に、グリッドはマス領域に描かれ、どちらも同じ `cellSize` の格子に乗る。ヒントは `Grid` に含めない(GLOSSARY §2)
- 領域とデータは分けて呼ぶ。`cellSize`・スクロール・中央寄せは領域の話で、`Grid` は px を知らない。同じマス領域に、モードや状態によって違うグリッドが描かれる
