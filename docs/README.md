# nonogram-js

ノノグラムを**作問**し、任意の Web ページに**タグを貼るだけで遊べる**ようにする JavaScript ライブラリとエディタ。

- 用語は [spec/GLOSSARY.md](spec/GLOSSARY.md) に従う。この文書で太字の語はすべてそこで定義している
- 正解図コードの形式は [spec/FORMAT.md](spec/FORMAT.md)
- 進捗コードとパズル ID の形式は [spec/PROGRESS.md](spec/PROGRESS.md)
- 埋め込みタグの仕様は [spec/EMBED.md](spec/EMBED.md)
- TODO は [tasklist.md](tasklist.md)

---

## 1. ゴール

| # | ゴール |
|---|---|
| G1 | はてなブログなど、記事に `<script>` を書ける場所なら**どこでも**、タグを貼るだけでプレイモードが動く |
| G2 | 作問モード(エディタ)はブラウザだけで完結し、GitHub Pages で公開する。サーバーは持たない |
| G3 | エディタで**書き出し**たタグを貼れば、そのままプレイモードになる |
| G4 | モノクロ問題とカラー問題を同じ仕組みで扱う |
| G5 | ハッカブル。正解図コードは公開仕様で、外部ツールから作っても読んでもよい |

### やらないこと

- サーバー側の保存・ランキング・アカウント
- WordPress ブロックなど特定 CMS 専用の実装(必要になったらアダプタとして別に作る)
- 正解図の秘匿(ネタバレ防止まで)
- 旧形式 `v1;…` の読み込み
- core の npm パッケージとしての公開。外部ツール向けには仕様(spec/)をドキュメントとして公開するだけにする。core は DOM に依存させず、必要になったら切り出せるようにしておく

## 2. 全体像

```
┌──────────── GitHub Pages ─────────────┐
│  /editor/          作問モード (Editor)   │
│  /player/v1/player.js   プレイモード      │ ← 埋め込み先から読み込まれる
└──────────────────────────────────────┘
        │ 書き出し(タグをコピー)
        ▼
┌──────────── 任意のブログ記事 ───────────┐
│ <div class="todays-mitsui__nonogram"          │
│      data-solution="v2;…">                    │
│ <script src=".../player/v1/player.js">        │
└──────────────────────────────────────┘
        │ player.js が埋め込み要素を探して描画
        ▼
   プレイモード(進捗は解答者の localStorage)
```

1. 作問者はエディタでパレットと正解図を作る(作問側の保存 = 可視領域 ⊆ データ領域)
2. 「書き出し」で、切り抜いた正解図コードを含む**埋め込みタグ**を作り、クリップボードにコピーする
3. 作問者はブログ記事にタグを貼る
4. `player.js` がページ内の**埋め込み要素**を見つけ、正解図コードをデコードし、ヒントを導出してプレイモードを描画する

## 3. 埋め込みタグ

タグの書き方、`player.js` のマウント・エラー・JavaScript API、互換性の約束は **[spec/EMBED.md](spec/EMBED.md)**(公開仕様)。

```html
<div class="todays-mitsui__nonogram" data-solution="v2;5x5;5x5;#000;Y2BkAEI4ADEZGIBCDAA" data-aspect-ratio="1:1">ここにノノグラム(パズル)があります。JavaScript が動く環境で開くと遊べます。</div>
<script src="https://todays-mitsui.github.io/nonogram-js/player/v1/player.js" defer></script>
```

ここには、公開仕様には書かない配信の運用だけを置く。

### 3.1 配信とバージョニング

- `player.js` は依存なしの単一ファイル(IIFE、minify 済み)
- **配信元は GitHub Pages**。リポジトリ名は `nonogram-js` で、URL は `https://todays-mitsui.github.io/nonogram-js/`。エディタと同じサイトに置く。HTTPS なので HTTPS のブログから読み込んでも混在コンテンツにならず、`<script src>` なので CORS も不要
- パスにメジャーバージョンを入れる(`/player/v1/`)。**埋め込みタグの仕様または正解図コードの形式を壊す変更をしたら v2 を新設し、v1 は残し続ける**。貼られた記事は書き換えられないため
- 目標サイズ: gzip 後 30 KB 以下

#### GitHub Pages で配るための運用ルール

| 制約 | ルール |
|---|---|
| キャッシュは 10 分固定で、自分では設定できない。修正は約 10 分で貼られた全記事に届くが、壊れた版も同じく全記事に届く | 同じメジャーバージョンの中では後方互換を守る。CI でテストが通ったときだけデプロイする |
| Actions のデプロイは毎回サイト全体を置き換える | 古いメジャーバージョン(`/player/v1/` など)がビルド成果物から消えないようにする。v2 を出すときは、v1 のソースを残して一緒にビルドするか、v1 の完成品をリポジトリに残してデプロイのたびに一緒に置く |
| Pages の URL はアカウント名・リポジトリ名に依存し、リポジトリ名を変えると旧 URL は転送されない | **独自ドメインは使わない**(github.io のまま)。その代わり GitHub のアカウント名(`todays-mitsui`)とリポジトリ名(`nonogram-js`)を変えない |

- jsDelivr(`cdn.jsdelivr.net/gh/…@<tag>`)は使わない。タグごとに中身が変わらない URL になり、貼られた記事に修正を届けられないため

## 4. プレイモード(Player)

### 4.1 機能

| 機能 | 内容 |
|---|---|
| 表示 | 埋め込み要素の中にウィジェット(キャンバス・ツールバー・操作ボタン)を描画する。キャンバスには行ヒント(左)・列ヒント(上)・マス領域。カラー問題ではヒント項目を色付きで表示 |
| ツールバー | 塗り(色ごと)/ バツ / 消しゴム。ツールの候補は GLOSSARY §5 の表どおり |
| ヒントで色を選ぶ | カラー問題では、ヒント項目(数字)をタップ / クリックすると、その色の塗りツールが現在のツールになる。ツールバーの色見本まで指を動かさずに済むようにするため。マウスでは項目の上でカーソルが指の形になる。作問モードのキャンバスでも同じ |
| 主操作・副操作 | GLOSSARY §5 どおり。副操作(右クリック・修飾キー+クリック)はツールに関係なくバツのトグル |
| ストローク | ドラッグでなぞったマスに、最初のマスで決まった記号を適用。最初に動いた向き(行か列)に固定する |
| 一致したヒント | ラインごとに `satisfied` を判定してグレーアウト |
| 解けた | 全ラインが `satisfied` になったら `solved`。盤面からバツを消して絵だけを見せ、記入をロックする。正解図には置き換えない(別解で解いた場合は解答者の絵が残る)。「解けました」と表示し、ヒントと罫線を薄くして絵を目立たせる(アニメーションなし、`aria-live` でも通知)。解けたあとはリセットだけでき、アンドゥでは戻らない |
| ギブアップ | 確認のうえ `revealed` にし、正解図を表示 |
| リセット | 確認のうえ盤面を全マス未記入に戻す。`revealed` も解除するので、ギブアップ後も解き直せる |
| アンドゥ / リドゥ | ストローク単位。保存しない |
| 罫線表示 | 操作ボタンで外周以外の罫線の表示を切り替える(`showGridLines`)。非表示時はバツも隠れる。解答者のその場の設定で、保存しない |
| 進捗の保存 | 盤面と `revealed` を localStorage に自動保存し、リロード後に復元 |

### 4.2 描画と見た目

- **Shadow DOM** の中に描画する。ブログテーマの CSS(`button`・`img`・`table` への一括スタイル)の影響を受けないため
- マス領域とヒント領域は **Canvas 2D** で描画する。マスが多くても DOM 数が増えず、テーマ CSS とも無関係。`devicePixelRatio` に合わせて高解像度化する
- バツは文字の「×」ではなく、マスの四隅から 20% 内側までの2本の対角線で描く。線は細く(CSS px で 1.25px、マスの大きさによらない)、色は薄い灰色(`#B8B8B3`)
- 画面イメージ: [プレイモードのデザインキャンバス](https://claude.ai/artifact/EvRonrUkbgY2FqPcVuH4EL)(非公開)
- ツールバー・ボタン類は Shadow DOM 内の通常の DOM 要素
- ツールバーはキャンバスの下に置く(吸着はしない。ウィジェットの高さは縦横比で決まり、画面に収まるため)
- ギブアップ・リセットの確認は、Shadow DOM 内の `<dialog>` をパズルの上に重ねて出す。`confirm()` は使わない(1記事に複数のパズルがあるとどれの確認か分からず、アプリ内ブラウザで出ないことがあるため)
- 色の区別の補助(表示番号の重ね表示など)は今はしない。作問者が区別しやすい色を選ぶ前提とする(Backlog)
- レイアウト(`ResizeObserver` で親の幅の変化に追従する)
  1. ウィジェットの幅 = 埋め込み要素の親の幅、高さ = 幅 × 縦横比(`aspectRatio`)
  2. キャンバス = ウィジェットからツールバー・操作ボタンを除いた残り
  3. ヒント領域とマス領域がキャンバスに収まる最大の `cellSize` を求め、16〜40px に丸める。余白は中央寄せ
  4. 16px を割るときは 16px にし、キャンバスの中でスクロールさせる。マス領域は `touch-action: none` なので、スクロールはヒント領域かスクロールバーで行う
  - ズーム・全画面表示はしない
- マス領域には `touch-action: none` を指定し、なぞり操作中にページがスクロールしないようにする
- 配色はライト / ダークの2種。`prefers-color-scheme` に従う。ダークでもマス領域の背景だけは常に明るいままにする(パレットは作問者が明るい背景で選んだ色なので、例えば黒1色の問題が見えなくならないように)。ダークにするのはヒント領域・ツールバー・操作ボタン・ダイアログ

### 4.3 進捗の保存

- 保存キー・`PuzzleId`・進捗コードの形式は [spec/PROGRESS.md](spec/PROGRESS.md)
- `crypto.subtle` が使えない環境(非 HTTPS)や localStorage が使えない環境では、保存せずに遊べるようにする

### 4.4 アクセシビリティ(最低限)

- ツールバーはキーボードで操作できる(`button` 要素、`aria-pressed`)
- 解けた・ギブアップなどの状態変化は `aria-live` で通知する
- マス領域のキーボード操作(矢印キー + Space)は後回し(tasklist 参照)

### 4.5 やらないこと

- 経過時間の表示(のんびり解くもので、急かさない)
- ヒント項目ごとの手動の消し込み(Backlog。作るときは進捗コードに済み印を足す)
- 古い進捗の掃除。localStorage の容量(約 5MB)に届くには数千問かかる。書き込みに失敗したら保存せずに遊べるようにするだけ

### 4.6 文言(叩き台)

すべて `src/i18n/ja.ts` に置く。`{…}` は差し込み。

#### 埋め込み要素のフォールバック(エディタが書き出すタグの中身)

> ここにノノグラム(パズル)があります。JavaScript が動く環境で開くと遊べます。

RSS リーダー・AMP・JS 無効の環境で読まれる。「何が欠けているか」と「どうすれば遊べるか」だけを書く。

#### エラー(ウィジェットの代わりに表示)

読むのは主に解答者なので、1行目は解答者向けにし、2行目に作問者向けの理由を小さく出す。

| 場面 | 1行目 | 2行目(理由) |
|---|---|---|
| 正解図コードが不正 | ノノグラムを表示できませんでした。 | 正解図コードが壊れています: {理由} |
| `data-solution` が空 | ノノグラムを表示できませんでした。 | `data-solution` 属性が空です |
| `data-mode` が未知の値 | ノノグラムを表示できませんでした。 | `data-mode` の値「{値}」には対応していません |
| ブラウザが非対応(`DecompressionStream` などがない) | このブラウザではノノグラムを表示できません。 | 新しいブラウザで開いてください |

正解図コードが不正なときの {理由} は FORMAT.md の不正条件ごとに用意する。

| 不正条件 | {理由} |
|---|---|
| フィールド数が足りない | 項目が足りません |
| 先頭が `v2` でない | 形式のバージョン「{先頭}」には対応していません |
| サイズが不正 | サイズ「{値}」の書き方が正しくありません |
| 可視領域がデータ領域より大きい | 可視領域がデータ領域より大きくなっています |
| パレット色が不正 | 色「{値}」の書き方が正しくありません(`#RGB` か `#RRGGBB`) |
| 色数が 255 を超える | 色が多すぎます(255 色まで) |
| base64url / deflate として不正 | マスデータを読み込めません |
| 展開後の長さが合わない | マスの数がサイズと合いません |
| マスの値が N + 1 以上 | パレットにない色が使われています |

#### 確認ダイアログ

| 場面 | 本文 | 実行ボタン | 取り消しボタン |
|---|---|---|---|
| ギブアップ | 答えを見ますか? 見たあとも、リセットすれば解き直せます。 | 答えを見る | やめる |
| リセット | 盤面を消して、最初からやり直しますか? | 消してやり直す | やめる |

- 実行ボタンは「はい」ではなく、何が起きるかを書く
- 初期フォーカスは取り消しボタンに置く

#### 状態の表示と通知(`aria-live`)

| 場面 | 画面の表示 | `aria-live` |
|---|---|---|
| 解けた | 解けました! | パズルが解けました |
| ギブアップ | 答えを表示しています | 答えを表示しました |
| リセット | (表示なし) | 盤面をリセットしました |
| 進捗を保存できない環境 | (表示なし。保存せずに遊べる) | — |

#### ツールバー・操作ボタン

| 対象 | ラベル | `aria-label`(ラベルが記号のとき) |
|---|---|---|
| 塗り(モノクロ) | 塗る | — |
| 塗り(カラー) | 色見本のみ | 色{表示番号}で塗る |
| バツ | × | バツを付ける |
| 消しゴム | 消す | — |
| アンドゥ / リドゥ | ↶ / ↷ | 元に戻す / やり直す |
| 罫線表示 | 罫線 | 罫線を表示(`aria-pressed`) |
| リセット | リセット | — |
| ギブアップ | 答えを見る | — |

#### エディタ

| 場面 | 文言 |
|---|---|
| 読み込み: 17 色以上 | このパズルは {N} 色あるため、エディタでは開けません(エディタで使えるのは 16 色まで)。プレイモードでは遊べます。 |
| 読み込み: 不正なコード | 読み込めませんでした: {理由}(プレイモードと同じ理由の文言) |

| 作品の削除 | 「{作品名}」を削除しますか? 元に戻せません。 |

## 5. 作問モード(Editor)

GitHub Pages で公開する単独の Web アプリ。

### 5.1 機能

| 機能 | 内容 |
|---|---|
| サイズ | 幅・高さを数値で指定(それぞれ 5〜100)。縮めても枠外のマスは保持する(可視領域とデータ領域の分離) |
| パレット | 1〜16 色。色の追加・削除・並べ替え・値の変更。並べ替え・削除時の `PaletteIndex` の振り直しはエディタが行う。削除した色のマスは背景にする(確認あり) |
| 描画 | 塗り(色ごと)/ 消しゴム。ストローク・トグルは GLOSSARY §5 どおり。ストロークの方向は固定しない(絵を描くため) |
| ヒントのプレビュー | 描いている絵から導出したヒントを、プレイモードと同じ見た目でリアルタイムに表示 |
| 一意解チェック | ソルバーでヒントだけから解き、結果を4段階で表示する(書き出しは止めない)。下の表 |
| テストプレイ | 同じ画面でプレイモードを開いて解いてみる。進捗は保存しない |
| 書き出し | 切り抜いた正解図コードから埋め込みタグを作り、コピーする。縦横比(縦長 / 正方形 / 横長)を選べ、プレビューにも反映する。初期値は正方形 |
| 読み込み | 正解図コード(または埋め込みタグ)を貼り付けて編集を再開する。17 色以上のコードは理由を示して読み込まない(プレイモードでは遊べる) |
| 作品の一覧 | 作品を複数持てる。一覧から開く・新規作成・複製・名前の変更・削除ができる(§5.4)。新規作成は 15x15・黒(`#000`)1色から始める |
| 作業の保存 | 開いている作品を localStorage に自動保存する。URL の `#` 以降にも正解図コードを載せ、URL で共有・再開できる(§5.4) |
| アンドゥ / リドゥ | 描画・サイズ変更・パレット変更の単位 |
| WebMCP | エディタの操作を WebMCP のツールとして公開し、ブラウザ内の AI エージェントが作問できるようにする(§5.3) |

#### 一意解チェックの結果

| 結果 | 判定方法 |
|---|---|
| ライン推論だけで解ける | ラインソルバー(1ラインずつの推論の繰り返し)で全マスが確定する。人間が論理だけで解けるのに近い |
| 一意だが仮置きが要る | ラインソルバーで止まるが、バックトラックで解が1つだけと分かる |
| 別解あり | バックトラックで解が2つ以上見つかる。2つ目の解を表示できるとよい |
| 判定打ち切り | バックトラックが時間制限内に終わらない |

- ラインソルバーが先に走り、確定しなかったときだけバックトラックに進む
- どちらも Web Worker で動かし、描画中の UI を止めない。描くたびに前の判定は中断する

### 5.2 後回しにする機能

- 画像(PNG など)からの取り込み(減色してパレットを作る)
- 平行移動・反転・回転
- 鑑賞モード用のタグの書き出し

### 5.3 WebMCP 対応

[WebMCP](https://webmachinelearning.github.io/webmcp/) は、Web ページが JavaScript の関数を「ツール」としてブラウザ内の AI エージェントに公開する API。エディタはこれに対応し、エージェントが UI と同じ操作で作問できるようにする。

#### 方針

- **UI と同じ道を通す**。エディタの状態変更はすべてコマンド(サイズ変更・パレット操作・描画など)として実装し、UI と WebMCP のツールはどちらも同じコマンドを呼ぶ。WebMCP 専用の状態や処理は持たない
- **1回のツール呼び出し = アンドゥ1回分**。エージェントの変更は画面にそのまま反映され、作問者がアンドゥで取り消せる
- **原子的にする**。入力が不正なら何も変えずにエラーを返す(一部だけ描かれた状態を残さない)
- **書き込み系のツールは、更新後の状態を返す**(`get_editor_state` と同じ形)。エージェントがヒントを見ながら描き直せるようにするため
- **プログレッシブ・エンハンスメント**。`document.modelContext` がなければ何もしない。WebMCP がなくてもエディタは完全に動く
- WebMCP 対応のコードは `src/editor/webmcp.ts` に閉じ込める。仕様はまだ Draft Community Group Report で、API の場所(`navigator.modelContext` → `document.modelContext`)も 2026 年中に変わった。変化を1ファイルで吸収する
- プレイモード(`player.js`)では公開しない(§5.3 末尾)

#### 正解図の文字列表現(行文字列)

エージェントが絵を読み書きしやすいよう、ツールの入出力では正解図を**行文字列**の配列で表す。正解図コード(deflate + base64url)はエージェントには読めないため。

| 文字 | 意味 |
|---|---|
| `.` | 背景(`empty`) |
| `1`〜`9`、`a`〜`g` | 表示番号(= `PaletteIndex + 1`)。`1` = 色1、`a` = 色10、`g` = 色16 |
| `-` | 変更しない(書き込み時のみ。重ね描き用) |

- 1文字 = 1マス、1要素 = 1行。上の行から並べる
- エディタの色数の上限は 16(§5.1)なので、行文字列で必ず表せる

#### ツール

| ツール | 種別 | 入力 | 内容 |
|---|---|---|---|
| `get_editor_state` | 読み取り | — | 作品名・サイズ・パレット(表示番号と色の値)・正解図(可視領域の行文字列)・行ヒント / 列ヒント・枠外のマスがあるか・アンドゥ / リドゥできるか |
| `set_size` | 書き込み | `width`, `height` | サイズ変更。枠外のマスは保持する(UI と同じ) |
| `add_color` / `update_color` / `remove_color` / `move_color` | 書き込み | 色の値・表示番号 | パレット操作。`PaletteIndex` の振り直しはエディタが行う。`remove_color` で消えた色のマスは背景になる |
| `draw_rows` | 書き込み | `x`, `y`, `rows: string[]` | `(x, y)` を左上として行文字列を書き込む。可視領域からはみ出したらエラー |
| `fill_cells` | 書き込み | `cells: {x, y}[]`, `color`(表示番号、`0` = 背景) | 指定したマスを1色で塗る / 消す |
| `clear` | 書き込み | — | 全マスを背景にする(枠外も含む) |
| `import_code` | 書き込み | `code` | 正解図コードまたは埋め込みタグを、新しい作品として開く。今の作品は作品の一覧に残る(UI の読み込みと同じ) |
| `export_embed_tag` | 読み取り | `aspect_ratio`(省略時は作品に選ばれている縦横比) | 書き出しの埋め込みタグと、切り抜いた正解図コードを返す。クリップボードにはコピーしない(コピーは作問者が UI で行う) |
| `check_uniqueness` | 読み取り | — | 一意解チェックの結果(Phase 4 のソルバーができてから) |
| `undo` / `redo` | 書き込み | — | UI のアンドゥ / リドゥと同じ |

- 読み取り系には `annotations.readOnlyHint: true` を付ける。`clear` は絵を丸ごと消すので `consequentialHint: true` を付ける(アンドゥで戻せるが、エージェント側に確認の機会を与える)
- 入力の名前は snake_case(`color_number`、`aspect_ratio`)。色は表示番号(1 始まり)で指す
- 書き込み系の結果と `get_editor_state` は JSON 文字列。エラーは `execute` が reject して返す(メッセージは英語)
- ツールの `description` は英語で書く(エージェントの解釈が安定するため)。用語は GLOSSARY の識別子に揃える
- 座標・サイズ・ブロックのルールなど、ノノグラムの前提は `get_editor_state` の `description` に短く書く

#### やらないこと

- プレイモードでの公開。エージェントに解かせても解答者の体験にならず、正解図は誰でもデコードできるので、解かせたい人は正解図コードを渡せば済む
- 宣言的 API(`<form toolname>`)。エディタはフォーム中心の UI ではなく、仕様からも外された
- 作品の一覧の操作(開く・削除など)。エージェントが開いている作品以外を書き換えられないようにする

#### オリジントライアル

- Chrome のオリジントライアルに登録し、公開版のエディタでも有効にする。トークンは `/editor/` の HTML に `<meta http-equiv="origin-trial">` で入れる
- トークンはオリジン `todays-mitsui.github.io` 単位で、同じアカウントの他の Pages にも効く(他のページは WebMCP を呼ばないので影響はない)
- トークンには期限がある。切れても機能検出で無効になるだけで、エディタは壊れない
- WebMCP が正式に出荷されたらトークンを外す

### 5.4 作品の保存

| localStorage のキー | 値 |
|---|---|
| `todays-mitsui/nonogram:editor:works` | 作品の一覧。`{ id, name, updatedAt, openedAt, aspectRatio }[]` の JSON。`openedAt` は最後に開いた日時、`aspectRatio` は書き出しで最後に選んだ縦横比 |
| `todays-mitsui/nonogram:editor:work:<id>` | 作品の中身。作問側の保存の正解図コード |

- `id` は作品を作ったときに `crypto.randomUUID()` で決める。名前の初期値は「無題 {作成日時}」
- 一覧と中身を分けるのは、一覧を開くたびに全作品の正解図コードを読まずに済ませるため
- 描画のたびに中身を保存し、URL の `#` も書き換える(`history.replaceState`。履歴は増やさない)
- URL の `#` に載せるのは正解図コードだけで、縦横比は載せない(表示設定なので、共有先で選び直せばよい)
- `#` 付きの URL を開いたら、同じ正解図コードの作品があればそれを開き、なければ新しい作品として取り込む。共有された URL を開いても、自分の既存の作品は上書きされない
- `#` なしで開いたら、最後に開いていた作品を開く。作品が1つもなければ新規作成する
- localStorage が使えない環境では一覧を出さず、URL の `#` だけで作業を保つ

## 6. 技術構成

| 項目 | 決定 | 理由 |
|---|---|---|
| 言語 | TypeScript(配布物は JavaScript) | 型で GLOSSARY の用語(`Mark`・`Tool` など)をそのまま表せる |
| ビルド | Vite。`player.js` はライブラリモードで IIFE 単一ファイル | エディタの開発サーバーと共用できる |
| 実行時依存 | なし | 埋め込み先の負担を小さく、外部 CDN に依存しない |
| deflate | `CompressionStream` / `DecompressionStream`(`'deflate-raw'`) | ブラウザ標準。非同期だが、プレイモード・エディタともに問題ない |
| UI(エディタ) | **Preact + Signals**。状態はコマンド経由でだけ更新し、結果を signal に載せる(§5.3) | フォームの多い画面を書きやすい。WebMCP からコマンドを呼んでも UI が自動で追従する。Canvas の描画コードはプレイモードと共有する |
| UI(プレイモード) | フレームワークなし | `player.js` は依存なし・gzip 30 KB 以下にするため |
| UI 文言 | **日本語のみ**。文言は `src/i18n/ja.ts` に集め、コードに直接書かない | あとで英語を足せるようにしておく |
| ライセンス | **MIT** | ハッカブルにする方針と合う |
| WebMCP | `document.modelContext.registerTool`。機能検出して、なければ何もしない | Chrome のオリジントライアル中。仕様は Draft |
| テスト | Vitest。core は Node で単体テスト | 形式・ヒント導出・ソルバーは純粋関数にする |
| 公開 | GitHub Actions で GitHub Pages にデプロイ | |
| 対象ブラウザ | 直近2年の Chrome / Edge / Safari(iOS 含む)/ Firefox | `deflate-raw` は Safari 16.4 以降 |

## 7. この文書で新たに決めること(案)

GLOSSARY・FORMAT に未定義のもの。合意できたら spec/ に移す。

### 7.1 サイズと色数の上限(決定)

- 正解図コード自体には上限を設けない(FORMAT.md のとおり)
- エディタで作れるサイズは幅・高さそれぞれ 5〜100 とする(5 未満はパズルとして成り立ちにくい)
- エディタで作れる色数は 1〜16。正解図コードの形式は 255 色まで表せるので、外部ツールで作ったコードはプレイモードでは遊べるが、エディタでは読み込めない
- プレイモードは描画できるかぎり受け付ける
